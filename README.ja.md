# PRch（パーチ）

GitHubのレビュー状況を、macOSのメニューバーから確認するアプリです。自分へのレビュー依頼と自分のopenなPRを、リポジトリごとにまとめて表示します。

![メニューバーから開いたPRch。スター付き・新着・更新のあるレビュー依頼をrepoごとに表示](docs/media/preview.jpg)

*架空データを使ったUIイメージです。*

## 起動

macOS 14以降、Swift 6 / Xcode 16以降、GitHub CLIが必要です。

```sh
brew install gh
gh auth login --hostname github.com
swift test
bash scripts/build-app.sh
open dist/PRch.app
```

初回起動時の設定画面で、監視したいOrganizationを入力して「保存して接続」を押します。設定後はウインドウを閉じ、メニューバーのPアイコンから使えます。Finderでアプリを開き直すと、通常のウインドウでも表示できます。Organizationはソースコードに固定していません。private repoには、GitHub CLIでログインしているアカウントと認証情報の閲覧権限が必要です。

## 監視対象

複数のOrganizationを追加して、同時に監視できます。Orgごとの「すべて」と、repoごとのチェックボックスで選択します。一部だけ選択したOrgは「−」表示になり、クリックすると全選択になります。検索中も「すべて」はOrg全体に適用します。

追加したOrgは全選択から始まります。「すべて」で全選択すると新しいrepoも自動で含み、個別に外したrepoは除外します。一度全解除すると、明示的にチェックしたrepoだけを監視します。旧版の単一Org・Include／Exclude設定も、監視範囲を変えずに引き継ぎます。

監視対象はメニューバーの件数・両方のタブに反映し、複数Orgの結果を集計します。複数Orgがあるときは、同名repoを区別できるよう一覧のグループ名と絞り込みに `Org/repo` を表示します。設定はこのMacに保存します。一覧内のリポジトリ選択は、一時的な表示の絞り込みです。

一覧のrepo名をクリックすると、そのrepoのPRを折りたたみ・展開できます。repo名を別のrepoの見出しへドラッグ＆ドロップすると、表示順を入れ替えられます。折りたたみ状態と順番は両方のタブ・スター付き・Pending欄で共通になり、更新・再起動後も維持します。折りたたんだPRも件数には含まれます。

## 表示

PRタイトルは14pt、補助テキストは11〜12ptを中心に表示し、読みやすい余白を設けています。

設定の「言語 / Language」で「システムに合わせる」「日本語」「English」を選べます。再起動せずに画面・状態・エラー・相対時刻・メニューバーの説明が切り替わり、選択は次回起動時も保持します。未対応のシステム言語は英語にフォールバックします。PRタイトルなどGitHub上のコンテンツは翻訳しません。

メニューバーとヘッダーはPRchのPマーク、FinderのアプリアイコンはForest Greenです。Pマークは背景に合わせて白黒が切り替わります。アイコンの元データは `Resources/Brand/` にあり、`bash scripts/generate-app-icon.sh` でmacOS用アイコンを再生成できます。

「私への依頼」は、自分に直接レビューを依頼されたPRと、自分がレビュー済みのopenなPRです。対応待ち／レビュー済みを切り替えられます。自発的にレビューしたPRも含まれます。チームだけに届いた依頼は初版では対象外です。

「自分のPR」は、自分が作ったopenなPR全体です。レビュー待ち、修正対応、承認済み、未依頼で絞り込めます。Botの自動レビューだけが付いたPRも含み、各レビュアーの状態を確認できます。PR一覧を開いているときに **⌘F** を押すと、検索欄にフォーカスが移ります。PR行をクリックすると `repo_name#pr_number` をクリップボードにコピーし、ダブルクリックでGitHubを開きます。右側の矢印で全レビュアーとチェックの詳細を表示します。

重要なPRには、行の右端や詳細画面の **☆** からスターを付けられます。**スター付き** は各タブの先頭にrepoごとにまとめて表示し、検索・repo・状態・新着の絞り込みを適用します。スターはGitHubアカウント別にこのMacへ保存し、更新・再起動後も保持します。レビュー状態・件数・未確認状態は変わりません。PendingにしたPRはスターを保持したままPending欄に置き、通常の一覧に戻すとスター付き欄へ戻ります。閉じた・マージされたPRは一覧から消えます。

「私への依頼」「自分のPR」の両方で、行の「…」メニューか詳細画面から **Pending（保留）** にできます。Pendingは一覧下部の折りたたみ欄にrepoごとに表示し、タブ・状態フィルタ・メニューバーの件数から除外します。検索とrepoの絞り込みは適用されます。「通常の一覧に戻す」で解除でき、更新・再起動後も保留を維持します。設定はGitHubアカウント別にこのMacへ保存し、GitHubのレビュー状態は変更しません。閉じた・マージされたPRは更新時に一覧から消えます。

メニューバーの標準表示は **↓ レビュー対応待ち（未レビュー・再レビュー）／↑ 自分のPRの修正対応** です。設定の **「自分のPRの集計」** で **「修正対応のみ」** または **「修正対応＋承認済み」** を選べます。承認済みの判定は一覧の表示設定に合わせ、Pendingは除外します。表示形式は「依頼と自分のPRの件数」「件数＋自分のPRのドット」「要対応の合計」「ドットだけ」から選べます。集計対象の選択はすべての表示形式に適用し、メニューバーに即時反映します。選択は再起動後も保持されます。0件の数字は表示せず、100件以上は99+と表示します。マウスを重ねると正確な件数と監視範囲を確認できます。

前回の確認から新しく届いたレビュー依頼に **NEW** を表示します。自分のPRを作成しただけでは新着扱いにしません。再レビュー依頼や、自分のPRのレビュー状態の変化には **更新** を表示します。自分への依頼の完了・解除や、一覧から消えたPRは通知せず、そのPRの未確認表示も消します。行の薄い背景と左端のライン、タブ・repoごとの件数で変化がわかり、「新着・更新のみ」で絞り込めます。メニューバーは新着ドットを表示し、設定で「＋件数」に切り替えられます。開いている間は強調を残し、閉じる・最小化する時に、開いたタブ全体を確認済みにします。検索・フィルタ・折りたたみ・スクロールで非表示のPRも含み、開いていないタブは未確認のままです。Pendingは対象外です。

初回取得や監視範囲の追加では、既存PRを一斉に新着扱いしません。以降の正常な取得でPRごとの状態を比較し、未確認状態はアカウント別に再起動後も保持します。自分のPRは人間のレビュアーの状態変化も対象です。自分のPRが「レビュー待ち（Waiting）」になる変化や、待っている間のレビュー依頼の追加・再依頼は通知せず、以前の未確認表示も消します。他のレビューが未完了でも、新しい承認などのレビュー結果は通知します。旧版で保存されたレビュー待ちの未確認表示は、最初の正常な更新で消します。タイトル・更新時刻・CI・Botだけの更新は通知しません。ポーリングの間に状態が変化して元に戻った場合は検出できません。保存するのはPR ID・状態のハッシュ・未確認の目印で、PRタイトルや本文は保存しません。

ヘッダーにはGitHubで設定しているプロフィール画像を表示します。読み込み中や画像を取得できない場合はイニシャルを表示します。

再レビュー依頼は以前の承認とは分けて扱います。修正要求した全員に再レビューを依頼すると、GitHub全体の判定が修正要求のままでも、自分のPRは「レビュー待ち（Waiting）」に戻ります。再依頼していない人の修正要求が残っている場合は「修正対応（Changes）」を維持します。

初期設定では、1人が承認しても他の人がレビュー待ちなら「レビュー待ち」のままです。設定の **「1人の承認で自分のPRを承認済みにする」** をオンにすると、人間の有効な承認が1件あれば、他のレビューが未完了・必要な場合も「承認済み（Approved）」にします。修正依頼を優先し、Botの承認・取り消された承認・再レビュー待ちの承認は数えません。表示・絞り込み・並び順に即時反映し、再起動後も保持します。各レビュアーの状態や「私への依頼」は変わりません。PRch内の表示設定なのでGitHubのマージ条件は変更せず、設定の切り替えだけで更新通知は発生しません。承認表示は、マージ可能であることを保証するものではありません。

1・2・5分間隔で自動更新します。接続エラーやタイムアウトは10秒・20秒・40秒・以降は最大60秒間隔で自動再試行し、次の再試行までの秒数を表示します。認証・API制限など、それ以外のエラーでは待ち時間を最大30分まで延ばします。更新完了時に次回の更新を予約し、手動更新を含め、成功すれば通常の間隔に戻ります。いずれかのOrgで接続エラーが起きた場合は、直前の全体の結果を残し、古い情報であることを表示します。一部のOrgだけの件数は表示しません。GitHub検索の結果が1,000件を超える場合にも警告します。

## キーボード操作

設定の「一般」→「キーボード」で「ショートカットを記録…」を押し、ControlまたはCommandを含むキーの組み合わせを入力します。PRchの起動中は、ほかのアプリからもそのキーでメニューバーのパネルを開閉できます。記録中はEscでキャンセル、Deleteで解除でき、競合で登録できない場合はエラーを表示します。ショートカットと操作モードはこのMacに保存します。

操作キーバインドは **Emacs（初期設定）／Vim／標準** から選べます。

| 操作 | Emacs | Vim | 全モード共通 |
| --- | --- | --- | --- |
| タブ・状態フィルタ・一覧の間を移動 | `Tab` / `Shift-Tab` | `Tab` / `Shift-Tab` | `Tab` / `Shift-Tab` |
| 次／前の項目を選択 | `C-n` / `C-p` | `j` / `k` | `↓` / `↑` |
| 詳細・展開／戻る・折りたたみ | `C-f` / `C-b` | `l` / `h` | `→` / `←` |
| 検索 | `C-s` | `/` | `⌘F` |
| 入力欄・詳細・設定から戻る／パネルを閉じる | `C-g` | `Esc` | `Esc` |
| PRをGitHubで開く／選択した見出しを開閉 | `Return` | `Return` | `Return` |
| 私への依頼／自分のPRへ切り替え | `⌘1` / `⌘2` | `⌘1` / `⌘2` | `⌘1` / `⌘2` |
| ショートカットモード（キーヒント） | `?` | `?` | `?` |

通常はヒントを表示せず、選択したEmacs／Vim／標準のキー操作ができます。どの操作モードでも `?` でショートカットモードに入り、タブ・状態フィルタ・PR行などに枠付きのキーを表示します。表示されたキーでその項目を操作し、PR行の場合は詳細へ移動します。対象を選ぶか、Esc・再度 `?` を押すと通常操作に戻ります（Emacsでは `C-g` も可）。2文字以上のラベルは順に入力し、Backspaceで1文字戻れます。Vimの `h/j/k/l` は移動用として残します。移動キーを押すとショートカットモードを終了して通常の移動を行います。スクロール中も割り当ては固定し、対象の変更・文字入力・設定画面への移動・パネルを閉じる操作でもヒントを終了します。

パネルを開く・開き直すときは、ナビゲーションにフォーカスを置きます。検索欄を選ぶか検索ショートカットを押すと文字を入力でき、開き直しても検索内容は残ります。

`C-` はControlです。初期状態では選択中のタブが操作対象になり、Tabを押さずに `C-f` / `C-b`（Vimでは `l` / `h`）でタブを切り替えられます。選択中の項目は枠で表示し、画面外へ移動するとスクロールします。タブと状態フィルタの段では、`C-b` / `C-f`、`h` / `l`、または `←` / `→` で選択を切り替え、上下移動で段を移動できます。一覧の先頭から上へ移動すると状態フィルタ、その上がタブです。PRが0件でも上の2段を操作できます。この2段でReturnを押すと下の段・一覧へ移ります。検索・フィルタ・リポジトリ順・折りたたみを反映した表示順で移動し、スター付きのPRやPending欄の開閉にも対応します。入力欄では通常の文字入力・編集を優先します。検索中のReturnは一覧（0件なら状態フィルタ）へ戻り、PRを開くには項目を選んで再度Returnを押します。日本語変換中は変換操作を優先します。

## OSSとしての構成

- SwiftUI / AppKit / Foundation / CarbonなどmacOS標準フレームワークのみ。Swiftパッケージへの外部依存なし。
- GitHubへの操作は読み取り専用。レビューの投稿・マージはしません。
- トークンはアプリで読み出さず、GitHub CLIの既存認証を使用します。
- PR本文やAPI応答はディスクに保存しません。テストは架空データのみ。
- MITライセンス、テスト、CI、ビルドスクリプトを同梱。
- 公開スクリーンショットは `--demo` で作成できます。

```sh
open dist/PRch.app --args --demo
```

別モードで起動するときは、先に起動中のPRchを終了してください。デモはGitHubに接続せず、設定も通常利用と分けています。

現状はGitHub.com・複数のOrganizationに対応する初版です。ログイン時の自動起動、通知、GitHub Enterprise、アプリ独自のOAuthは未実装です。ビルドスクリプトはローカル利用向けの署名を行います。バイナリを一般配布する際のDeveloper ID署名・公証は別途必要です。

詳しい状態判定や開発手順は [README](README.md) を参照してください。
